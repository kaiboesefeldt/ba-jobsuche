# Coding Guidelines

- Clean Code: sprechende Namen, kleine Funktionen mit klarer Verantwortung, flache Kontrollflüsse und möglichst einfache Lösungen. Duplizierung, unnötige Zustände und implizite Annahmen vermeiden; Fehler an Schnittstellen ausdrücklich behandeln.
- Python-Code einschließlich Tests auf Englisch schreiben. Öffentliche und interne Funktionen im Laufzeitcode einschließlich Parameter und Rückgabewert mit Typannotationen versehen; bei Tests Typannotationen verwenden, wenn sie das Verständnis verbessern. Dynamische externe Daten an Grenzen validieren; `Any` nur verwenden, wo der Datentyp tatsächlich offen ist.
- Für Verhalten und Fehlerfälle aussagekräftige, unabhängige Unit-Tests schreiben. Externe Dienste simulieren; reguläre Tests laufen ohne Netzwerk. Bei Fehlerkorrekturen einen reproduzierenden Test ergänzen.
- Möglichst hohe Zweigüberdeckung anstreben und für den Laufzeitcode mit Coverage.py messen. Der aktuelle Grenzwert beträgt 100 % Gesamtüberdeckung aus Anweisungen und Zweigen; `coverage report` schlägt darunter fehl. Auch bei erfülltem Grenzwert die tatsächliche Zweigabdeckung und fehlende Fälle prüfen: Eine Kennzahl belegt keine Testqualität. Ausnahmen begründen und nicht bloß zum Erreichen einer Zahl ausschließen.
- Die zyklomatische McCabe-Komplexität beträgt höchstens 5 je Funktion. Ruff prüft dies deterministisch mit C901; Funktionen vor Erreichen der Grenze entlang ihrer Verantwortung einfach halten. Begründete Ausnahmen müssen im Code und im Review nachvollziehbar sein.
- Ruff für Linting und Formatierung ausführen. Tests, Coverage und Ruff vor Abschluss prüfen; siehe [Nutzung](../nutzung.md#entwicklung).
